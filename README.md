# IT Tracking — Mobile App

แอปมือถือเขียนด้วย React Native + Expo (TypeScript) รันได้ทั้ง iOS และ Android จากโค้ดชุดเดียว
รวมถึงเปิดบนเบราว์เซอร์ (คอม) ได้ด้วย — ดูหัวข้อ "รันบนคอมผ่านเบราว์เซอร์" ด้านล่าง

**เวอร์ชันปัจจุบัน: Expo SDK 57** (React Native 0.86, React 19.2) — ต้องใช้ Expo Go เวอร์ชันที่รองรับ SDK 57

## เปิดใน VS Code ครั้งแรก

1. เปิดโฟลเดอร์ `mobile/` ใน VS Code (แยกหน้าต่างจาก `server/` หรือเปิด workspace เดียวที่มีทั้งสองโฟลเดอร์ก็ได้)
2. ต้องมี Node.js 20+ (SDK 57 ไม่รองรับ Node 18 แล้ว)
3. ติดตั้ง Expo CLI ผ่าน npx (ไม่ต้องติดตั้งแยก ใช้ `npx expo` ได้เลย)
4. รัน:
   ```
   npm install
   ```

## ติดตั้งแอป Expo Go บนมือถือคุณ (วิธีทดสอบเร็วที่สุด)

1. โหลดแอป **Expo Go** จาก App Store (iOS) หรือ Play Store (Android)
2. ต่อมือถือกับคอมพิวเตอร์ให้อยู่ **WiFi วงเดียวกัน**

> **ถ้า Expo Go ขึ้นว่า "Project is incompatible with this version of Expo Go"** แปลว่าเวอร์ชัน SDK ของแอป Expo Go ไม่ตรงกับของโปรเจกต์
> - บน **iOS** ติดตั้ง Expo Go ย้อนเวอร์ชันไม่ได้ (App Store ให้แค่ตัวล่าสุด) → ต้องอัปเกรดโปรเจกต์ให้ตรงกับ SDK ที่ Expo Go รองรับ
> - บน **Android** โหลด Expo Go เวอร์ชันเก่าได้จาก `https://expo.dev/go?sdkVersion=<เลข SDK>&platform=android&device=true`
> - หรือเลี่ยงปัญหานี้ทั้งหมดด้วยการรันบนเบราว์เซอร์ (`npm run web`) หรือทำ development build

## ตั้งค่า URL ของ API

คัดลอก `.env.example` เป็น `.env` แล้วเลือกว่าจะชี้ไปที่ไหน

**แบบที่ 1 — ชี้ไป API ที่ deploy แล้วบน Railway (แนะนำ)**

```
EXPO_PUBLIC_API_URL="https://xxxx.up.railway.app"
```

ใช้ได้ทุกที่ทันที ทั้งเว็บบนคอมและมือถือจริง ไม่ต้องรัน server เองและไม่ต้องคอยแก้ตาม IP ที่เปลี่ยนทุกครั้งที่ย้าย WiFi

**แบบที่ 2 — ชี้ไป server ที่รันในเครื่องตัวเอง** (ใช้ตอนแก้โค้ดฝั่ง server ไปด้วย)

- เปิดบนเว็บที่เครื่องเดียวกัน → `http://localhost:4000`
- เปิดบนมือถือจริง/emulator → ต้องใช้ IP ของเครื่องคอม เพราะมือถือมองไม่เห็น `localhost` ของคอม
  - Windows: เปิด cmd พิมพ์ `ipconfig` ดูที่ `IPv4 Address`
  - Mac: System Settings > Network ดู IP ที่แสดง
  - ใส่เป็น `http://192.168.1.42:4000` (เปลี่ยนเป็น IP ของคุณ)
  - Windows Firewall บล็อกพอร์ต 4000 จากเครื่องอื่นโดยค่าเริ่มต้น เปิดก่อนด้วยคำสั่งนี้ (PowerShell แบบ Administrator):
    ```
    New-NetFirewallRule -DisplayName "IT Tracking API" -Direction Inbound -Protocol TCP -LocalPort 4000 -Action Allow
    ```
- อย่าลืมรัน server ทิ้งไว้ด้วย (`npm run dev` ในโปรเจกต์ server) ไม่งั้นแอปจะเรียก API ไม่ติด

> ⚠️ **ค่านี้ถูกฝังลงในไฟล์ที่ build ตั้งแต่ตอน build ไม่ได้อ่านตอนรัน**
> แก้ `.env` แล้วต้องรีสตาร์ทใหม่เสมอ ถ้ายังเห็นค่าเดิมให้ล้าง cache ด้วย `npx expo start --clear`

## รันแอป

```
npm start
```
จะมี QR code ขึ้นในเทอร์มินัล — เปิดแอป Expo Go บนมือถือแล้วสแกน QR code นั้น แอปจะโหลดขึ้นมือถือคุณจริงๆ ทันที (ไม่ต้อง build อะไรทั้งนั้นตอนทดสอบ)

## รันบนคอมผ่านเบราว์เซอร์

```
npm run web
```
เปิด `http://localhost:8081` แอปจะทำงานเหมือนบนมือถือทุกอย่าง (ใช้ทดสอบได้โดยไม่ต้องมีมือถือ/emulator)

**Layout ปรับตามขนาดจอให้อัตโนมัติ** (เส้นแบ่งที่ความกว้าง 900px — ดู `src/hooks/useResponsive.ts`):
- **จอกว้าง ≥ 900px (คอม)** — เมนูเป็น sidebar ด้านซ้าย, การ์ดสถิติเรียงแถวเดียว, กราฟในหน้ารายงานวางคู่กัน 2 คอลัมน์, หน้า "งาน" แสดงรายการงาน + รายละเอียดคู่กันแบบ master-detail (คลิกงานแล้วดูรายละเอียดฝั่งขวาได้เลยไม่ต้องเปลี่ยนหน้า), ฟอร์มต่างๆ จำกัดความกว้างและจัดกึ่งกลาง
- **จอแคบ < 900px (มือถือ)** — แถบเมนูล่าง (bottom tab bar) พร้อมปุ่ม + ตรงกลาง, การ์ดสถิติ 2x2, ทุกอย่างเรียงคอลัมน์เดียวเหมือนเดิม

> หมายเหตุ: บนเว็บ `expo-secure-store` ใช้ไม่ได้ (เป็นข้อจำกัดของไลบรารีเอง) — `src/storage/secureStorage.ts` จึง fallback ไปใช้ `localStorage` ให้อัตโนมัติเฉพาะตอนรันบนเว็บ ส่วนบนมือถือยังเก็บ token แบบเข้ารหัสด้วย SecureStore เหมือนเดิม

## Deploy แอปเว็บขึ้น Vercel

แอปเวอร์ชันเว็บเป็นไฟล์ static ล้วน (HTML + JS) จึงขึ้น Vercel ได้ตรงๆ ไม่ต้องมี server ของตัวเอง
ไฟล์ `vercel.json` ในโปรเจกต์ตั้งค่า build ไว้ให้หมดแล้ว ไม่ต้องกรอกอะไรเพิ่มในหน้าเว็บ Vercel

**ขั้นตอน**

1. Push โค้ดโปรเจกต์นี้ขึ้น GitHub repo
2. ไปที่ https://vercel.com/new → **Import** repo นั้น
3. **ก่อนกด Deploy** ไปที่ **Environment Variables** เพิ่ม

   | Key | Value |
   |---|---|
   | `EXPO_PUBLIC_API_URL` | `https://xxxx.up.railway.app` (URL ของ API บน Railway) |

   ต้องเป็น **https** เท่านั้น ถ้าใส่ http เบราว์เซอร์จะบล็อกทุก request ด้วย mixed content
   และต้องใส่**ก่อน**กด Deploy ครั้งแรก เพราะค่านี้ถูกฝังลงไฟล์ตั้งแต่ตอน build — ถ้าใส่ทีหลังต้องกด Redeploy

4. กด **Deploy** รอสักครู่จะได้โดเมนมา เช่น `https://it-tracking.vercel.app`
5. **กลับไปที่ Railway** ตั้งตัวแปร `CORS_ORIGIN` ของ API เป็น

   ```
   https://it-tracking.vercel.app,https://it-tracking-*.vercel.app
   ```

   ตัวที่สองจำเป็นเพราะ Vercel สร้าง subdomain ใหม่ทุกครั้งที่ push — ถ้าไม่ใส่ preview deploy จะเรียก API ไม่ได้เลย

**ทดสอบ build ในเครื่องก่อนได้** (ได้ผลลัพธ์เหมือนที่ Vercel จะได้เป๊ะๆ)

```
npx expo export --platform web
```

ไฟล์จะออกมาที่โฟลเดอร์ `dist/`

## ถ้าเจอ "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" ตอนสมัคร/เข้าสู่ระบบ

แอปจะ log URL ที่มันพยายามเรียกไว้ในเทอร์มินัลที่รัน `npm start` เสมอ (บรรทัด `[IT Tracking] API base URL: ...`) เช็คทีละข้อ:

1. **ฝั่ง server รันอยู่จริงไหม** — ต้องเปิด terminal อีกหน้าต่างแยกไปที่โฟลเดอร์ `server` แล้ว `npm run dev` ค้างไว้ตลอดเวลาที่ทดสอบแอป (ปิดหน้าต่างนั้นแอปจะเชื่อมต่อไม่ได้ทันที)
2. **มือถือกับคอมอยู่ WiFi วงเดียวกันจริงไหม** — WiFi บ้าน/มหาลัยบางที่แยกเครือข่ายอุปกรณ์แต่ละตัวออกจากกัน (client isolation) ทำให้มือถือมองไม่เห็นคอมแม้ต่อ WiFi เดียวกัน ลองใช้ hotspot จากมือถือปล่อยให้คอมต่อแทนดูก็ได้ (สลับบทบาท)
3. **IP ในไฟล์ `mobile/.env` ยังตรงกับที่ `ipconfig` บอกอยู่ไหม** — IP เปลี่ยนได้ทุกครั้งที่ต่อ WiFi ใหม่ ถ้าเปลี่ยน .env ต้องรัน `npx expo start -c` ใหม่ (แฟลก `-c` ล้าง cache เพื่อให้อ่านค่า .env ใหม่จริงๆ)
4. **Windows Firewall บล็อกพอร์ต 4000 อยู่หรือเปล่า** — ตอน `npm run dev` รันครั้งแรก Windows อาจเด้งถามว่าอนุญาต Node.js ให้เข้าถึงเครือข่ายไหม ต้องกด "Allow" (ถ้าพลาดกด Cancel ไปแล้ว ต้องไปแก้ที่ Windows Defender Firewall > Allow an app ด้วยตัวเอง)

  navigation/               กำหนดเส้นทางเปลี่ยนหน้าจอทั้งแอป
  screens/                  แต่ละหน้าจอของแอป
  components/                ชิ้นส่วน UI ที่ใช้ซ้ำหลายหน้า (ปุ่ม, การ์ดใบงาน ฯลฯ)

## หน้าจอที่ทำเป็นโค้ดจริงแล้ว

Sign In, Register, Join Property, Create Hotel, Job Detail (เช็คลิสต์ + บันทึก + มอบหมายผู้รับผิดชอบ + ตั้งวันที่ต้องการให้เสร็จ + แนบ/ดูรูปภาพ + ยกเลิก/เสร็จสิ้น/ลบงาน), Add Job (มี dropdown ประเภทงาน IT Support + เลือกวันที่ต้องการให้เสร็จ + แนบรูปภาพ), Edit Job, Notifications, Settings, Switch Hotel, Team Management

พร้อม **แถบเมนูล่าง (bottom tab bar)** จริงตามที่ออกแบบไว้ใน Figma — 4 แท็บ: หน้าหลัก (Dashboard) / งาน (All Jobs) / รายงาน (Reports, มี 4 กราฟ: สัดส่วนตามสถานะ, แนวโน้ม 7 วัน, งานตามประเภท, งานตามผู้รับผิดชอบ) / โปรไฟล์ (Profile, มีปุ่มออกจากระบบ) พร้อมปุ่ม + ตรงกลางลอยขึ้นมาสำหรับเพิ่มงานใหม่ (`src/navigation/BottomTabs.tsx`)

ไอคอนทั้งแอปใช้ `@expo/vector-icons` (Ionicons) แทน emoji ทั้งหมด — เพิ่ม/เปลี่ยนไอคอนได้ที่แต่ละไฟล์หน้าจอโดยตรง

**แนบรูปภาพในใบงาน — หลายรูปต่อใบงาน (สูงสุด 10 รูป)** — ถ่ายจากกล้อง หรือเลือกจากคลังภาพได้ทีละหลายรูป อัปโหลดขึ้น server ทันที แสดงเป็นตารางรูปย่อ แตะเพื่อดูเต็มจอและกดลูกศรเลื่อนดูรูปถัดไปได้ (`src/components/PhotoGallery.tsx`)
เก็บไฟล์ไว้ในเครื่อง/บน Railway Volume ตอน dev ไม่ต้องตั้งค่าอะไรเพิ่ม (ดู `server/README.md` สำหรับตอน deploy จริง)

**แจ้งเตือนแบบ Push** — แจ้งเตือนอัตโนมัติเมื่อมีคนมอบหมายงานให้คุณ หรือมีบันทึกใหม่ในงานที่คุณรับผิดชอบ แตะที่การแจ้งเตือนแล้วพาไปหน้ารายละเอียดงานนั้นได้เลย **ต้องตั้งค่า EAS project ก่อนถึงจะใช้งานได้จริง** ดูขั้นตอนด้านล่าง

**หน้าจอที่เพิ่มเข้ามาครบตาม Figma mockup แล้ว:**

- **Edit Job** (`EditJobScreen.tsx`) — แก้หลายฟิลด์พร้อมกันแล้วกด "บันทึก" ครั้งเดียว (ต่างจาก Job Detail ที่บันทึกทันทีทีละอย่าง) ส่งขึ้น server เฉพาะฟิลด์ที่เปลี่ยนจริง เข้าได้จากปุ่มดินสอในหน้า Job Detail
- **Notifications** (`NotificationsScreen.tsx`) — ประวัติการแจ้งเตือนในแอป จัดกลุ่ม วันนี้/เมื่อวาน/วันที่ พร้อมจุดแดงนับที่ยังไม่อ่านบนกระดิ่งในหน้า Dashboard, กด "อ่านทั้งหมด" ได้, แตะแล้วเปิดใบงานที่เกี่ยวข้อง
- **Settings** (`SettingsScreen.tsx`) — ทางเข้าสลับโรงแรม/จัดการทีม, สวิตช์เปิด-ปิด push (เก็บไว้ในเครื่อง มีผลจริงกับการลงทะเบียน token), ประวัติการแจ้งเตือน, เวอร์ชันแอป, ออกจากระบบ
- **Switch Hotel** (`SwitchHotelScreen.tsx`) — เลือกจากโรงแรมที่เป็นสมาชิกอยู่แล้ว แสดงบทบาท/จำนวนสมาชิก/สถานะรออนุมัติ (เดิมใช้หน้า Join Property ซ้ำ)
- **Team Management** (`TeamManagementScreen.tsx`) — เฉพาะ Admin: รหัสเชิญทีม (แชร์/สร้างใหม่), อนุมัติ-ปฏิเสธคำขอเข้าร่วม, รายชื่อสมาชิกและเอาสมาชิกออก

**เพิ่มเข้ามาภายหลัง:**

- **ลืมรหัสผ่าน** (`ForgotPasswordScreen.tsx`) — ขอรหัสยืนยัน 6 หลักทางอีเมล แล้วตั้งรหัสใหม่ในหน้าเดียว (ไม่ต้องทำ deep link) ตั้งสำเร็จแล้ว server จะเพิกถอน session ทุกเครื่องอัตโนมัติ
- **แก้ไขโปรไฟล์ & เปลี่ยนรหัสผ่าน** (`EditProfileScreen.tsx`) — แก้ชื่อ/อีเมล และเปลี่ยนรหัสผ่าน (เปลี่ยนแล้วเตะอุปกรณ์อื่นออกทั้งหมด แต่เครื่องที่เปลี่ยนยังใช้ต่อได้)
- **ธีมมืด** — เลือกได้ 3 แบบในหน้าตั้งค่า: ตามระบบ / สว่าง / มืด สลับทันทีไม่ต้องรีสตาร์ท และจำค่าไว้ในเครื่อง
  ชุดสีอยู่ใน `theme/tokens.ts` (`lightColors` / `darkColors`) — หน้าจอเรียกผ่าน `useTheme()` และ `useThemedStyles()` จาก `theme/ThemeProvider.tsx` แทนการ import `colors` ตรงๆ
- **รายงาน: กรองช่วงเวลา + ส่งออก CSV** — เลือก ทั้งหมด/7 วัน/30 วัน/เดือนนี้ และดาวน์โหลด CSV (บนเว็บดาวน์โหลดตรง, บนมือถือเปิดแผงแชร์) ไฟล์มี BOM ให้ Excel อ่านภาษาไทยได้ถูกต้อง
- **รายการงานแบ่งหน้า + ค้นหาอัตโนมัติ** — เลื่อนถึงท้ายรายการแล้วโหลดหน้าถัดไปเอง (หน้าละ 20) และค้นหาหลังหยุดพิมพ์ 400ms โดยไม่ต้องกด Enter

**ยังไม่ได้ทำ:**

- **แจ้งเตือนทางอีเมล / แจ้งเตือนเมื่อใกล้เกิน SLA** — ยังไม่มีฟิลด์ SLA ในฐานข้อมูล จึงไม่ใส่สวิตช์ที่กดแล้วไม่เกิดอะไรขึ้น
- **ส่งออกเป็น PDF** — ตอนนี้ส่งออกได้เฉพาะ CSV

## ตั้งค่า Push Notification ให้ใช้งานได้จริง

การแจ้งเตือนต้องมี **EAS project id** ก่อนถึงจะขอ push token ได้ (ครั้งเดียว ไม่มีค่าใช้จ่าย ไม่ต้อง build จริง):

1. สมัครบัญชี Expo ฟรีที่ https://expo.dev (ถ้ายังไม่มี)
2. ในโฟลเดอร์ `mobile` รัน:
   ```powershell
   npx eas login
   npx eas init
   ```
   `eas init` จะถามยืนยันชื่อโปรเจกต์ แล้วเติม `extra.eas.projectId` ลงใน `app.json` ให้อัตโนมัติ
3. รัน `npx expo start -c` ใหม่ แล้วลองมอบหมายงานให้ตัวเอง (หรือให้เพื่อนร่วมทีม) ดู — ควรมีแจ้งเตือนขึ้นมา

**ข้อจำกัดตอนทดสอบผ่าน Expo Go:** push notification ทำงานได้เฉพาะบน **iPhone จริง** เท่านั้น (ไม่ใช่ simulator) — บน **Android ผ่าน Expo Go ใช้ไม่ได้** (ข้อจำกัดของ Expo Go เอง ไม่ใช่บั๊กของแอปนี้) ต้องรอทำ [development build](https://docs.expo.dev/develop/development-builds/introduction/) หรือ build จริงขึ้น Play Store ถึงจะทดสอบบน Android ได้ ฝั่ง iOS ที่คุณใช้ทดสอบอยู่ไม่ติดปัญหานี้

## ทำแอปให้พร้อมขึ้น App Store / Play Store จริง

ใช้ **EAS Build** ของ Expo (ฟรีมีโควต้าให้ในระดับเริ่มต้น):

```
npm install -g eas-cli
eas login
eas build:configure
eas build --platform android   # ได้ไฟล์ .aab ส่งขึ้น Play Store
eas build --platform ios       # ต้องมีบัญชี Apple Developer (ปีละ ~3,500 บาท) ก่อนถึงจะส่งขึ้น App Store ได้
```

สิ่งที่ต้องเตรียมเพิ่มก่อนส่งจริง: ไอคอนแอป (`assets/icon.png`), ภาพ splash screen, คำอธิบายแอปและภาพหน้าจอสำหรับหน้าร้านค้า, บัญชี Apple Developer + Google Play Console

## ความปลอดภัยที่ทำไว้ให้แล้ว

- Token เก็บด้วย `expo-secure-store` (เข้ารหัสในเครื่อง ไม่ใช่แค่เก็บ text ธรรมดา)
- Access token หมดอายุเร็ว (15 นาที) ระบบ refresh ให้อัตโนมัติโดยผู้ใช้ไม่รู้สึกสะดุด
- ออกจากระบบ (logout) จะแจ้งเซิร์ฟเวอร์ให้เพิกถอน token จริง ไม่ใช่แค่ลบในเครื่อง
